# 部署与结构审计

## 本轮已改进

- 构建前强制执行 TypeScript 检查。
- 每次构建都重新生成 Tailwind CSS，避免旧 `dist` 缓存漏掉新样式。
- Vite 和自定义预览构建都使用相对资源路径，可部署到子目录。
- `share/` 与 `dist/` 作为生成目录忽略，不混入源码。
- 本地资料库按类型、数据库、服务、Hook、复用组件和页面分层。
- 面向用户、部署人员和 Codex 的文档已经分目录。

## 仍需处理

- 仓库当前没有 CI/CD、正式环境变量模板或部署平台配置。
- 文件选择器缺少自动化 E2E，现阶段主要靠浏览器人工回归。
- IndexedDB 容量与清理策略由浏览器决定，Web 端无法提供绝对永久保证。
- Python CAIE 服务与 Web 前端仍是两个独立部署单元。
- 仓库尚无基线 Git 提交，无法做可靠的历史差异或回滚。
- Vite 标准构建的主 JavaScript 包约 633 KB，后续应按页面做动态加载。

## 建议的发布门槛

1. 建立基线提交并保护主分支。
2. CI 运行 `npm run typecheck`、`npm test`、`npm run build`。
3. 在 Chrome、Safari 和移动端完成导入、重启恢复、分享与存储配额测试。
4. 明确正式域名，避免域名迁移造成 IndexedDB 数据隔离。
