# A-Level 搜题模块

这个目录保存时间规划 App 的 A-Level 搜题能力。模块目标是让学生通过文字、题号、Paper 信息或图片识别信号，在本地 CAIE Mathematics 9709 题库中找到相似题、知识点和解题思路。

## 模块职责

- 把题库数据、文本清洗、题号解析、图片指纹、OCR 兜底信号和搜索排序拆开，避免页面组件承担过多业务逻辑。
- 支持 Web MVP 的搜题页，也为小程序端和后续真实题库接入保留清晰边界。
- 在没有完整后端题库时，用本地 seed database 验证产品流程。

## 核心文件

- `types.ts`：题库、图片信号、OCR 结果和搜索结果的数据结构。
- `cieMathQuestionBank.ts`：当前 CAIE Mathematics 9709 seed 题库。
- `textTools.ts`：文本清洗、关键词切分和 paper-code 解析，例如 `9709/11/M/J/24 Q3`。
- `imageFingerprint.ts`：浏览器端图片指纹，用于未来精确或近似图片匹配。
- `ocrEngine.ts`：浏览器端 OCR 能力检测和识别封装。
- `questionLocator.ts`：把图片识别结果转换成可搜索的题目信号。
- `questionSearchEngine.ts`：相似题评分、排序和题库统计。

## 已实现能力

- 按关键词、题号、Paper、知识点和组件组搜索。
- 从文件名、用户输入和图片指纹中构建搜索信号。
- OCR 不可用时降级到文件名 + 图片指纹 + 手动输入。
- 记录最近搜索，供搜题页快速复用。
- 输出题目、topic、Paper 信息、匹配原因和解题思路。

## 设计边界

- 页面层只负责上传、输入、筛选和展示；搜索评分逻辑留在本模块。
- 当前题库是 MVP seed data，不代表完整 CAIE 官方题库。
- 后续接入真实后端时，应优先替换数据源和索引层，保持页面交互和类型边界稳定。

## 变更记录规则

任何影响搜题准确度、题库结构、OCR 策略或搜索排序的修改，都需要纳入下一次阶段性 change 文档或根目录 [CHANGELOG.md](../../../CHANGELOG.md)。日常小改不需要立即创建新分支；阶段汇总时先用 50 字内的人话 list 概括变化，再补充细节和相对上一次存档的差异。
